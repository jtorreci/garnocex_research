# Voronoi Misallocation Risk: Reproducibility Package

Reproducibility package for the manuscript *"A Probabilistic Framework for Misallocation Risk in
Voronoi Tessellations: Theory and Empirical Validation"*.

**Status:** in preparation for submission.

## Headline results

Every figure in the table is regenerated by `pipeline/canonical_numbers.py` from the shipped OD
tables, not typed in by hand.

| Quantity | Value |
|---|---|
| Municipalities / physical facilities | 383 / 46 |
| Effective facilities after 15 km consolidation | **34** |
| Misallocated municipalities (Euclidean Voronoi vs network-optimal) | **49 of 383 = 12.8 %** |
| Lognormal predictive interval for the misallocation count | **52.6, 95 % PI [46.0, 59.5]** (contains the observed 49) |
| Network-optimal assignments recovered | **97.7 % using 2n route queries** |
| Municipality–facility routes evaluated | 17 618 |
| Scaling factor on the predictor domain | median β = 1.426, s = 0.288, m = 0.413 |

Configuration recorded in `pipeline/canonical_numbers.json`: network `carreteras.shp` (IGN roads and
streets, no *camino*/*senda*), graph snap tolerance 5 m, facilities `Plantas_Ext.shp`, network
distance `d_r` = total cost (entry + network + exit), 15 km consolidation, 4000 bootstrap draws,
seed 42.

## Reproducing the manuscript numbers

```bash
python pipeline/canonical_numbers.py      # ~15 s -> pipeline/canonical_numbers.json
```

That one script reproduces the counts and the predictive intervals above. It reads the OD tables in
`pipeline/od/` and `codigo/coordenadas_municipios.csv`; no routing, no QGIS and no network
connection are required.

The remaining pipeline scripts each produce one block of the manuscript:

| Script | Produces |
|---|---|
| `pipeline/validate.py` | acceptance test of the statistical core (run this first) |
| `pipeline/descriptive_stats.py` | descriptive statistics of β for the Section 4.2 table |
| `pipeline/ranking_allpairs.py` | distributional ranking on the all-pairs municipality domain |
| `pipeline/calibration_precision.py` | precision of the prediction against pilot-sample size (the "≈200 units → ±12 %" claim) |
| `pipeline/knearest_accuracy.py` | accuracy of k-nearest candidate sets against the network optimum (the 97.7 % / 2n claim) |
| `pipeline/anisotropy_alpha.py` | anisotropy coefficient α and its power as a classifier of misallocation |
| `pipeline/refit_spatial.py`, `pipeline/bym2_only.py` | Moran's I, log-CAR, BYM2 and spatial LOOCV refits |
| `pipeline/residual_diagnostics.py` | whitened-residual autocorrelation diagnostic |
| `pipeline/sensitivity_table.py` | the configuration-sensitivity table (`tab:sensitivity_config`) |
| `pipeline/network_composition.py` | class composition of the IGN transport network, by length |
| `pipeline/run_case.py` | recomputation of one network case (the paved case) |
| `pipeline/replicate_published.py` | faithful replication of the historical assignment script |
| `pipeline/make_figures.py`, `pipeline/make_spatial_figures.py`, `pipeline/refine_submission_figures.py` | regenerate the manuscript figures from the canonical outputs |
| `pipeline/run_routing.py` | headless QNEAT3 OD-matrix runs — needs the QGIS interpreter and the shapefiles, see below |

The three analysis lines in `Revision/analyses/` are independent and each ships its own `README.md`,
a runnable `run.py` and its canonical inputs:

| Line | Produces |
|---|---|
| `Revision/analyses/A1_spatial_carbym/` | Bayesian log-CAR and BYM2 posterior fits on log(β), spatial LOOCV, Moran's I on residuals |
| `Revision/analyses/A2_distributional/` | Wasserstein-1 and Anderson-Darling ranking of candidate distributions on the municipality and facility domains |
| `Revision/analyses/A3_anisotropy/` | per-municipality anisotropy coefficient α = β_max / β_min, with its ROC against observed misallocations |

```bash
cd Revision/analyses
conda env create -f environment.yml     # or: pip install -r requirements.txt
python A1_spatial_carbym/run.py
python A2_distributional/run.py
python A3_anisotropy/run.py
```

Pre-generated figures and LaTeX tables live under `Revision/analyses/outputs/`.

## Original (v1) pipeline, kept for traceability

`codigo/`, `scripts/`, `tables/` and the top-level `*.py` scripts (`distributional_analysis.py`,
`distributional_sensitivity_s.py`, `make_qq_final.py`) are the original pipeline that produced the
first version of the paper. They are retained so that every step of the project can be traced, but
**their outputs do not always correspond to the manuscript**: `codigo/misallocated_municipalities.csv`
lists **88** municipalities under the unconsolidated 46-facility configuration, whereas the manuscript
reports **49** under the 34 effective facilities. Use `pipeline/` for the manuscript numbers.

The figure scripts in `figuras_clean/` are likewise the original ones (`generate_figure{1..15}.py`,
plus the study-area and Q-Q helpers) and `figuras_clean/FIGURES_DOCUMENTATION.md` documents what each
of them does.

## Road-network and facility shapefiles

Reproducing the OD matrices from raw data with `pipeline/run_routing.py` needs two layers that are
**not redistributed here** (the network alone is ≈620 MB):

- `carreteras.shp` — the IGN roads-and-streets transport network (*Red de Transportes*, Instituto
  Geográfico Nacional), as recorded in `pipeline/canonical_numbers.json` and
  `pipeline/network_composition.py`;
- `Plantas_Ext.shp` — the 46 facility locations.

The package does not record a download URL for either layer, so they are **available from the authors
on request**. Routing must also run under the QGIS interpreter (`python-qgis-ltr.bat`) with the QNEAT3
plugin installed. The OD matrices it produces are already shipped in `pipeline/od/`, so no result in
this package requires re-running the routing.

## QGIS plugin

`qgis_plugin/voronoi_risk_toolbox/` packages the framework as a QGIS Processing plugin — **Voronoi
Risk Toolbox** (v0.2.0) — with five algorithms that practitioners can run on their own facility and
road-network data:

1. **Voronoi Assignment** — Euclidean nearest-facility assignment, distance ratio R.
2. **Beta Calculator** — network scaling factor β = d_network / d_Euclidean (needs QNEAT3).
3. **Safety Bands** — misallocation probability per municipality, safety-band polygons.
4. **Misallocation Detector** — per-feature misallocation flags and distance savings.
5. **Anisotropy Map** — anisotropy coefficient α = β_max / β_min per origin (needs QNEAT3).

Requirements: QGIS 3.22+ and the [QNEAT3](https://plugins.qgis.org/plugins/QNEAT3/) plugin for the
algorithms that compute network distance. Installation, parameters and a usage walkthrough are in
`qgis_plugin/README.md`, `qgis_plugin/INSTALL_AND_TEST.md` and `qgis_plugin/docs/USER_MANUAL.md`;
the theoretical background is summarised in `qgis_plugin/docs/THEORY.md`.

## Study area

Extremadura, Spain: 383 municipalities, 46 aggregate production facilities, 41 635 km².

## Requirements

- Python ≥ 3.8 for the v1 scripts (`requirements.txt`).
- `Revision/analyses/requirements.txt` or `environment.yml` for the A1–A3 lines (PyMC and friends).
- QGIS 3.22+ with QNEAT3 only for the plugin and for `pipeline/run_routing.py`.
